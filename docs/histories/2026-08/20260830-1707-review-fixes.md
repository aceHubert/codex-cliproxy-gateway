### 🛠 Changes Overview
**Scope:** CLI（src/cli.ts）、TOML 读取（src/toml.ts）、测试与文档

**Key Actions:**
- **[--cpa-only 回归 models --sync]**: 按用户裁决删除 `config --cpa-only`，模式切换回归 `models --sync [--cpa-only]`（布尔开关，无 flag = split），与 `--restart-codex` 一步到位；`config` 仅保留设置打印与 `--log on|off`。评审 P1 的「空目录启用」「TOML 漂移 no-op」随该入口删除而闭合。
- **[TOML literal string]**: `readRootTomlString` 支持单引号值；新增 `hasRootTomlKey`，`applyModelCatalogToml` 对「键存在但值不可解析」（多行字符串等）显式报错，堵住单引号/多行写法绕过非受管守卫的路径。
- **[参数白名单]**: runCli 增加 `COMMAND_OPTIONS`，白名单外的 `--key` 报 `Unknown option`，拼写错误不再被静默忽略后部分生效。
- **[重启重试]**: `InstallState.pendingRestart` 标记 persist→restart 顺序中的失败；下一次 `models --sync` / `config` 自动补一次重启，`controlGateway("restart")` 成功后清除。
- **[审计补全与脱敏]**: `syncGatewayConfigFile` 的版本迁移与 websocket 清理写盘也留审计（含 configVersion）；审计值统一脱敏，URL query（`?token=...`）不再明文落盘，diff 仍按原始值比较。
- **[文档同步]**: README/usage、`model-catalog-dynamic-refresh-plan.md`、split-websocket 计划决策记录与执行计划均改为新语义。

### 🧠 Design Intent (Why)
8 项评审问题中，两项 P1 的根因是 `config --cpa-only` 这个第二入口绕开了 `models --sync` 的选择校验与 TOML 一致性逻辑；用户确认模式切换本就与 `--restart-codex` 绑定后，删除该入口比修补更简单可靠。其余 P2 属于真实缺陷：TOML 解析盲区会覆盖用户配置（违反"不修改非受管字段"），审计缺口让"每次配置变更都有记录"不成立，参数拼写错误部分生效与重启失败不可重试都会造成配置与运行态不一致。
