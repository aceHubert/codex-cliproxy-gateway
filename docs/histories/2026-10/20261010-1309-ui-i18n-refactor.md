### 🧠 Design Intent (Why)
自研词典的插值（`formatTemplate` replace）、键名一致性、复数与类型推导均靠手工维护，成本随词条增长（孤儿键无检测、拼错变量名静默产出 `{page}` 残留、5+ 处双语混写）。i18next 是用户显式决策引入的事实标准方案：插值/类型化键名/复数/命名空间由库承担，资源全量内联不需要 backend。实施中两个关键取舍：① 词典文件由计划的 JSON 改为 `as const` 的 `.ts`——实测 tsc 对 JSON 导入的字符串值统一拓宽为 `string`，插值变量名无法推导（直连 `useTranslation` 亦然），启用计划风险节预授权的 `.ts` 退路；② `LangProvider` 整体移除——react-i18next 自带语言变化重渲染，`<html lang>` 同步与持久化收敛到实例监听，减少一层样板。
