状态：双地域已实施；国内版真实调用验证通过，国际版排队恢复已实现并验证行为，
国际版在账号并发占用下的完整恢复成功路径仍待一次真实排队排空的观察。

最新修正（2026-10-02 晚）：

- **排队根因修复**：上游并发/额度受限时，Qoder 在流首返回
  `statusCodeValue=403` + `body.code=403/10605` + 嵌套 `isQueued` 的排队信封，
  旧实现把它当致命错误，客户端 1～5 秒收到「Qoder 上游响应失败」。
  对照官方 CLI 1.1.65 逻辑（`isQueued:true`/`serviceAvailable:false` 等待、
  `isQueued:false` 等待 `retryAfterSeconds` 后重发推理），新增
  `src/qoder/queue.ts` 排队恢复层：剥离排队帧、等待期间帧边界重置空闲计时、
  就绪或排队连接被服务端关闭（约 120 秒）时按剩余次数重试（默认共 2 次），
  恢复耗尽给出 `qoder_queued_limited` 分类；`src/qoder/sse.ts` 提供共享帧解析。
- **国内版实施**：真实推理端点为 `https://gateway.qoder.com.cn`（取自
  国内版 CLI 日志与实测；`openapi.qoder.com.cn` 的 algo 路径返回 503）。
  凭据 `~/.qoder-cn/.auth`（`QODERCN_CONFIG_DIR` 覆盖）与国际版同构，
  签名、编码、目录、推理、排队协议完全一致；目录含 qfmodel（price_factor=0）。
  双地域目录（`qoder-intl/`、`qoder-cn/` 前缀，显示 `Qoder-INTL/`、`Qoder-CN/`）
  在单个 `qoder` 开关下自动发现、独立缓存与刷新。
- 显示分组使用 `Qoder-INTL`／`Qoder-CN`，取代原有的地域在前写法；
  调用 ID 不变。各模型从自己的 `context_config` 自动识别最大档位，
  推理同步发送 `parameters.context_length`，原始 `max_input_tokens` 单独保留。
  当前 Max 与 Flash 均为 1M，客户端有效预算约为 950k；没有手动上下文配置。
1M 参数的 Flash 短请求实测成功，未验证满容量输入。

创建日期：2026-10-02（北京时间）。

## 目标

借鉴参考项目的调用协议，在 codex-cliproxy 内实现 Qoder 适配器。
config 只提供一个 `qoder` 配置开关，自动发现本机国内版和国际版登录，
动态生成 `INTL-Qoder` 与 `CN-Qoder` 两组账号可用模型目录。
按模型所属地域只读消费对应 CLI 授权，调用对应服务，类似 CodeBuddy/WorkBuddy。
先以 Qwen3.8-Flash 验证推理与 Responses 转换，供本机 Codex 客户端使用。
确保模型映射明确、凭据不泄露、现有上游不受影响，并通过真实客户端验证。
免费状态以实际调用和官方活动规则为准，不将当前限时活动写成永久承诺。

## 范围

- 包含：国内版和国际版自动发现、项目内 Qoder 凭据读取、目录拉取与缓存、模型路由、
  Responses 流式响应及工具调用、必要的配置和文档、回滚方法。
- 包含：研究当前账号完整目录和更新机制；首轮推理验收使用 Flash，
  其他模型只展示服务端确认的能力，不主动产生付费测试请求。
- 包含：明确本机 CLI 登录刷新与网关只读消费的边界，验证失败和计费观测。
- 不包含：直接安装、运行或分发 `qodercli2api`，以及依赖其 HTTP 服务。
- 不包含：公网部署、多人共享、
  自动签到、账号轮换、额度绕过和直接执行模型生成的工具代码。
- 本次实施只接入国际版。测试使用临时网关和 Codex 会话，不修改本机安装配置，
  不启动常驻服务；国内版不生成目录，明确拒绝调用。

- 本机国际版 Qoder CLI 版本：1.1.65，已有登录。
- 协议参考：[Liki4/qodercli2api](https://github.com/Liki4/qodercli2api)。
  以下测试证明参考调用方式可行，不代表最终实现使用该代理。
- 实测源码提交：`b8b595f`；构建环境：Go 1.25.5，macOS。
- 临时代理监听 `127.0.0.1:18377`，启用独立客户端鉴权。
- 测试使用登录文件的隔离副本；验证结束后已停止服务并清理副本。
- CLI 模型目录包含 `Qwen3.8-Flash`；最小请求返回 `QODER_FLASH_OK`，
  `total_credits=0`，实际模型键为 `qfmodel`。
- `/v1/responses` 非流式请求返回 `QODER_PROXY_OK`，HTTP 200。
- `/v1/chat/completions` 流式请求返回 `QODER_STREAM_OK`，以 `[DONE]` 结束。
- Responses 返回虚拟工具 `echo_probe` 的 `function_call`，包含参数及 `call_id`。
- 回传 `function_call_output` 后，Responses SSE 返回
  `QODER_TOOL_ROUNDTRIP_OK`，正常发出 `response.completed`。
- 代理测试请求的 `usage.billable` 均为 `false`。
  `usage.credits` 和 `original_credits` 仍为非零计算值；
  未独立核对账户账单，不能将计算值直接解释为实际扣费。

### 国内版与国际版认证隔离（2026-10-02）

- 当前官方安装文档区分两个 CLI：国际版入口 `qoder`、底层 `qodercli`，
  npm 包 `@qoder-ai/qodercli`；国内版入口 `qodercn`，
  npm 包及 SDK 引用的可执行名为 `@qodercn-ai/qoderclicn` / `qoderclicn`。
- 国际版默认配置根为 `~/.qoder`，可由 `QODER_CONFIG_DIR` 或启动参数覆盖；
  本机验证使用的登录目录为 `~/.qoder/.auth`。
- 国内版当前官方默认根为 `~/.qoder-cn`，可由 `QODERCN_CONFIG_DIR` 覆盖。
  参考项目提到的 `~/.qoderworkcn` 不能当作当前官方 CLI 的默认目录；
  国内版具体认证文件布局尚未在本机验证。
- 国际版 PAT 入口为 `https://qoder.com/account/integrations`，变量为
  `QODER_PERSONAL_ACCESS_TOKEN`；国内版入口为
  `https://qoder.cn/account/integrations`，变量为 `QODERCN_PERSONAL_ACCESS_TOKEN`。
- 两者登录状态与默认本地存储分开，不假定令牌能跨地域复用；
  不能只替换 API 域名就沿用另一版授权。实现国内版时，
  认证路径、服务地址、模型目录及缓存身份必须按版本隔离。
- 本机 PATH 已发现国际版 `qoder`、`qodercli`，未发现 `qodercn`、`qoderclicn`；
  `~/.qoder/.auth` 存在，`~/.qoder-cn` 和参考项目的 `~/.qoderworkcn` 不存在。
  未扫描其他安装位置，也未读取或展示任何令牌内容。
- 官方依据：[国际版认证](https://docs.qoder.com/cli/authentication)、

### 模型目录更新调查（2026-10-02）

**参考项目 `qodercli2api`：没有定时远端拉取模型。**

- 固定提交 `b8b595f` 的 `main.go:86` 中，`loadCatalog()` 读取显式目录文件，
  或解密 `~/.qoder/.models/<账号标识>/catalog-v6`，与内置表合并。
- `app.go:357` 只在服务启动时调用一次 `loadCatalog()`，随后创建模型解析器。
- `app.go:323` 的 30 分钟定时器调用 `ensureFresh()`，刷新的是登录令牌，
  不是模型目录；运行期间不会自动重读 CLI 更新后的目录文件。
- 内置合并还会保留服务端目录之外的模型，不适合作为账号可用模型的权威来源。
- 上次临时验证使用隔离登录副本，未复制模型缓存，所以只加载了内置表；
  当时缺少 Flash 不能解释为本机 CLI 目录没有 Flash。

**本机官方国际版 Qoder CLI 1.1.65：存在动态拉取和后台同步。**

- 只读检查本机可执行文件内的目录模块，得到路径
  `/api/v2/model/list?Encode=1`；GET 请求通过认证上下文的
  `prepareRequest(..., "GET", "auth", ...)` 准备，不能当作无鉴权公开 API。
- 常量为 `gv=10`、`bv=120000`、`Co=100000`、`yv=6`：
  分别对应非强制拉取最短间隔 10 秒、后台同步间隔 2 分钟、
  共享缓存新鲜窗口 100 秒及缓存格式版本 6。
- 初始化先读账号隔离的共享磁盘缓存；需要新鲜目录且缓存过期时拉远端。
  另有缓存优先初始化入口，不能概括为所有启动都强制联网。
- `startSyncInterval()` 在 0～30 秒随机延迟后进行首次同步，
  随后每 2 分钟执行 `syncWithCache()`；进程退出后不继续运行。
- 同步先检查共享缓存：缓存仍新鲜则跳过远端请求；文件已变化则重新加载。
  缓存缺失或过期时才调用 `fetchFromRemote()`。
- 响应摘要不变时仍更新同步时间，并触碰缓存修改时间；变化时保存新目录。
- 以上是本机 1.1.65 的代码证据，不是官方对未来版本的稳定接口承诺。
  尚未在本项目实现国际版目录 GET 并核对完整响应结构及最终 URL。

**本项目 CodeBuddy：启动拉取、周期刷新和请求驱动缓存同时存在。**

- `src/codebuddy/catalog.ts:437` 请求 `GET <endpoint>/v3/config`。
- `src/codebuddy/index.ts:127` 默认启动即强制刷新；每 16 分钟强制刷新，
  关闭适配器时清除定时器。
- 缓存 TTL 为 6 小时，用于请求驱动的新鲜度判断；不是定时器间隔。
- 刷新并发合并；失败保留同账号的最近成功目录，请求驱动失败冷却 30 秒。
- 缓存按产品、地域和账号身份隔离；目录变化时过期 Codex 的模型缓存。

补充参考：[fengyinxia/qoder2api](https://github.com/fengyinxia/qoder2api)
的 `qoder_auth.py` 直接 GET `/algo/api/v2/model/list?Encode=1`，
`openai_bridge.py` 使用 600 秒 TTL、请求触发更新，并非后台定时刷新。

### 单开关与双目录方案（用户确定）

- 持久化 config 只增加 `qoder: boolean`，缺省关闭。
  不增加 `qoderRegion`、分别控制 CN/INTL 的开关、授权内容或手工目录路径字段。
- `qoder=true` 时同时检查两个地域的官方配置与登录，
  尊重各自配置根环境变量，缺省使用 `~/.qoder` 和 `~/.qoder-cn`。
  安装路径用于辅助识别版本，不能仅因 CLI 不在 PATH 就否定已有登录文件。
- `qoder=false` 或现有 `upstreamOnly=true` 时，不启动目录拉取和定时器，
  不拦截 Qoder 请求，与现有 CodeBuddy/WorkBuddy 适配器的禁用语义一致。
- 仅国际版登录有效时生成 `INTL-Qoder`；仅国内版有效时生成 `CN-Qoder`；
  两版均有效时同时生成。无登录时不展示虚构模型，提供对应登录指引。
- 两个地域独立加载凭据和目录；一个地域登录损坏、过期或目录接口失败时，
  记录脱敏状态，不影响另一个地域，也不把异常静默当作登录缺失。
- `INTL-Qoder`、`CN-Qoder` 是确定的目录展示分组名。
  对外模型 ID 必须包含地域标识，即使模型同名也能明确选择授权；
  ID 的具体格式实施前对齐现有目录约定，不将展示分组名与协议 ID 混为一谈。
- 调用顺序固定为：解析模型地域 → 获取该地域当前账号凭据 → 校验该账号目录模型 →
  构造该地域服务请求 → 转换响应。禁止跨地域授权、模型重名合并或失败自动切地域。
- 模型 key、显示名、能力来自各地域实际目录；账号可能不同，模型与额度不假定一致。
- 网关自己的目录缓存分别命名为 `qoder-intl-catalog.json`、`qoder-cn-catalog.json`，
  缓存身份包含地域、账号摘要和适配修订；登录变更时只使所属地域缓存失效。
- 共用确定一致的目录生命周期与协议转换代码；域名、认证读取、请求签名及地域差异
  经核对后由内部地域 profile 管理，不暴露成多个用户配置字段。

## 风险

- 私有协议变化：代理文档兼容基线为 CLI 1.1.34，而本机为 1.1.65。
  当前成功不代表后续版本持续兼容；固定验证版本并保留升级回归步骤。
- 模型回退与计费：参考代理的未知模型可能回退到 `auto`。
  本项目必须按当前目录解析模型，拒绝未知模型，不做跨模型付费回退。
- 目录误导：测试代理的模型接口仍包含其他内置模型。
  正式接入只能展示实际获准使用的模型，不直接照搬整个代理目录。
- 凭据生命周期：网关不刷新或写回官方登录文件；登录过期时返回重新登录指引。
  账号变更或登录文件变化后重新读取，并使旧账号目录失效。
- 目录更新：动态模型可能新增、下线、禁用或修改能力。
  原子替换同账号完整目录，不只追加，不把本地内置表当作最新账号权限。
- 免费活动变化：`billable=false` 是本次请求的结果，不是长期保证。
  记录计费观测字段和异常处理，避免只按 `credits` 数值判断实际扣费。
- 客户端兼容：基础 Responses 成功不能证明完整 Codex 工作流可用。
  必须继续验证工具往返、上下文管理、取消及失败恢复。

## 里程碑

### 1. 接入方案收敛

1. 参考固定版本调用协议，独立实现 `src/qoder/`，不依赖第三方代理服务。
2. 验证国际版模型目录 GET 的实际 URL、鉴权、响应编码及账号场景结构；
   核对显示名、内部 key、启用状态、上下文、视觉、推理及可得的活动字段。
3. 核对国内版 CLI 的实际授权布局、目录和推理协议，确定与国际版可共用的边界；
   当前本机没有国内版登录，国内版真实端到端验收需在具备对应授权时进行。
4. 用远端目录确认 Flash 显示名与 `qfmodel` 映射；
   确定 `INTL-Qoder`、`CN-Qoder` 分组及带地域的模型 ID、未知模型拒绝策略。
5. 确定只读认证、官方 CLI 续期及错误指引；禁止泄露凭据或使用其他账号目录。
6. 确定 Codex 所需压缩和传输行为，列出实际支持与不支持的能力。

### 目录刷新设计（拟定，待国际版目录实测后定稿）

1. 借鉴 CodeBuddy 的目录存储与生命周期模式：启动刷新、后台定时刷新、
   请求驱动过期检查、并发合并、同账号最近成功目录回退。
2. 初始候选间隔为 2 分钟，缓存新鲜窗口为 100 秒，参考本机 Qoder CLI；
   不直接沿用 CodeBuddy 的 16 分钟和 6 小时常量。
3. 读取官方 CLI 已更新的共享缓存时可跳过冗余远端请求；
   独立拉取应有超时、失败退避及可注入的时间和定时器。
4. 两个地域独立刷新、退避和回退，刷新失败不影响另一地域。
   网关自己的目录缓存只保存模型元数据与地域、账号身份摘要，原子写入；
   切换账号不复用旧目录，格式损坏不导致展示其他账号或内置付费模型。
5. 远端成功后完整替换目录，处理新增、移除、禁用和能力变化；
   内容变化时刷新网关与 Codex 的模型缓存，手工拉取入口也走同一逻辑。
6. 首次拉取失败且无可信目录时返回明确状态，不伪造成功；
   回退旧目录时标记陈旧，不能将历史免费标记作为当前扣费保证。

### 2. 最小接入实现

1. 将 Qoder 适配器组合进现有网关，沿用 CodeBuddy 的本机访问及认证边界。

   不引入未经对应地域及账号确认的模型。

   不把 Qoder 登录凭据放进网关配置。

## 验证方式

- CLI 基础检查：`qoder --version`、`qoder --list-models`。
- 最小 CLI 请求：

  ```bash
  qoder -p --model Qwen3.8-Flash --tools '' \
    --no-session-persistence --output-format json \
    --max-model-request-retries 0 '只回复 QODER_FLASH_OK，不使用任何工具。'
  ```

- 代理协议检查：Responses 非流式与 SSE、Chat SSE、虚拟工具调用和结果回传。
- 已验证的临时代理参数：

  ```text
  -addr 127.0.0.1:18377
  -default-model qfmodel
  -model-map {"Qwen3.8-Flash":"qfmodel","*":"qfmodel"}
  ```

  上述通配映射仅用于隔离验证，正式接入需拒绝未知模型，不能照搬为路由策略。

- 观测检查：真实上游模型键为 `qfmodel`、HTTP 状态、流式完成事件、
  工具参数与 `call_id`、`billable` 及账户实际用量；日志不得输出凭据。
- 仓库验证：先跑针对性测试，再执行 `bun run check`。
  后台单元测试设置最长 60 秒超时。
- 目录专项测试：启动刷新、2 分钟候选周期、缓存新鲜度、手工刷新、
  同步请求合并、失败退避、同账号旧缓存回退、账号切换隔离、目录新增和移除、
  禁用与能力变更、Codex 缓存失效、关闭适配器后定时器停止。
- 双地域专项测试：开关关闭、仅 INTL、仅 CN、双登录、都无登录、
  同名模型不同授权、一个地域失败另一个正常、单地域切账号、
  自定义配置根路径、拒绝跨地域缓存复用、禁止失败自动切地域。
- 国内版使用合成凭据和模拟服务覆盖上述逻辑，不能将模拟通过宣称为真实调用通过；
  最终分别记录两版真实端到端验收状态。
- 回滚检查：禁用 Qoder 适配器、恢复受管配置备份，
  确认现有上游和 Web UI 正常。
