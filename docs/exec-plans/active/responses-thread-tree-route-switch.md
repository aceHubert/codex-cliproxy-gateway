# 主会话与关联线程的上游双向切换

> 状态：代码实施与自动化验证完成，已重启本机网关，真实模型切换验收进行中。
> 分支：`codex/responses-thread-route-switch`。未提交；计划保留 active。

## 目标

在混合路由模式下，支持主线程从官方切到 CLIProxy，也能从 CLIProxy 切回官方。
主线程决定整个关联线程树的上游：subagent、guardian 及多层子线程统一跟随，
不因其文件配置中的裸模型名而独立走官方。已有 WS 与目标上游不一致时重新建连，
后续握手和 HTTP/SSE 请求不得被旧的永久 CPA 绑定拉回错误上游。
具有独立模型选择的 side 会话按自己的模型决定上游，视为独立路由根；
它的 subagent/guardian 跟随 side，不跟随其 fork 来源会话。

## 范围

- 包含：主线程路由更新、父子关系保留与动态继承、Responses WS 双向重连、
  HTTP/SSE 降级一致性、图片 turn 路由关联、回归测试和真实客户端验收。
- 不包含：独立且无 parent 的标题线程，其现有路由保持不变。
- 不包含：改变 Codex CLI/Desktop 的预热时机、单独制作 prewarm 豁免补丁。
- 不包含：更改 Realtime、插件协议、增加连接池、网关缓存完整对话并代替客户端重放。
- 不包含：让所有子线程使用主线程的模型；统一上游与认证，保留子线程自己的模型名。
- `upstreamOnly=true` 时默认上游继续直通，不因裸模型触发官方切换；插件边界保持现状。

## 背景

### 已接受的设计说明

- 独立无parent的 `thread_title` 按自身模型路由，与主会话通道隔离；不按时间窗口
  或共享session猜测归属。场景12已验证正常生成；官方额度耗尽时标题可能生成失败，
  属于保持独立官方通道的已知限制，不作为本次待修复技术债。
- CPA WebSocket 没有网关级 `websocket` 配置开关，不按GPT模型前缀门控传输能力；
  由上游决定支持与回退，网关保留握手失败时的426降级。恢复旧开关不是当前待办。


### 已确认的问题

1. `checkFrameRouting()` 只处理 official → CLIProxy；CLIProxy 上的裸模型帧继续转发。
2. `decideThreadRoute()` 用 `cpaThreads: Set<string>` 单向记录 CPA 归属，
   同线程及父线程继承可以覆盖后续官方模型选择。
3. 子线程继承时会将自己的 ID 写入同一集合，未保留用于动态跟随的父子关系。
   只删除主线程标记不能解除已经独立记录的子线程绑定。
4. TUI 启动就按持久化 model 建立连接，用户之后的模型选择可能复用该连接；
   Desktop 在用户发送首条消息时才建立用户会话连接，可先选择模型。
   两者暴露的是同一个双向切换缺口，不把预热本身视为独立修复目标。
5. 旧版本同线程的裸模型标题请求曾促使实现禁止反向切换；后续记录已确认独立
   `thread_title` 无 parent、不共享主会话连接。该独立线程不在本次范围内。
6. subagent/guardian 的模型来自配置，通常没有前缀。直接把所有裸模型判断为官方，
   会破坏“主会话切到 CLIProxy 后关联流量全部走 CLIProxy”的目标。
7. 2026-11-06 17:30–17:31 的 side 样本带 `history_initialization=warm_fork`、
   `forked_from_thread_id` 和 `thread_source=user`，没有 parent 请求头。
   它打开时以沿用的 CLIProxy 模型预热，随后官方 `gpt-6.1-terra` 请求仍复用
   CLIProxy WS。当前网关不读取 fork 字段，此次走错源于 side 自己的旧连接与绑定，
   不是通过 fork 字段继承来源会话路由。side 自己的 guardian 则带指向 side 的 parent。

## 方案与约束

### 1. 主会话持有可更新的路由

- 区分“根线程自己的路由决定”和“子线程继承关系”，不再把二者压平为 CPA 集合。
- 根线程当前真实请求的模型选择决定默认上游，允许 official / cliproxy 双向更新。
- HTTP Responses 的可解析正文 `model` 优先于握手提示，避免旧 hint 污染降级请求；
  缺少正文模型时才采用 hint。预热正文 `generate=false` 不覆盖已有根路由。
- side 与普通用户主线程享有相同的独立模型选择权；`forked_from_thread_id` 只描述
  上下文来源，不建立路由继承关系。来源会话与 side 切换上游时不得互相修改路由。
- 保存直接父子关系，子线程在新请求时解析所属主会话的当前路由；不复制永久 CPA 值。
- 不用 `session-id` 推测关联；它可以被多个线程共享，只保留日志聚合用途。
- 支持多层继承，防止环形关系导致无限解析；清理状态时不得将已知继承线程静默当作
  独立官方线程。生命周期、缺失父节点与网关重启后的行为在实施前明确并补测试。

### 2. 先确定线程角色，再判断最终上游

| 情形 | 规则 |
| --- | --- |
| 无父关联的主线程真实模型请求 | 按模型前缀决定并更新自己的上游 |
| 可独立选模型的 side / fork 用户会话 | 按自身模型更新上游，不跟随 fork 来源 |
| 有父关联的 subagent / guardian | 跟随主会话当前上游，不以裸模型触发官方切换 |
| side 的 subagent / guardian | 跟随 side 的当前上游，不跨越 fork 关系继承来源会话 |
| 多层子线程 | 沿父子关系解析，不保留脱离根线程的旧绑定 |
| 独立、无 parent 的标题线程 | 保持现有自身路由，不纳入其他主会话 |
| 无模型控制帧 | 不作为模型切换信号；不因父路由变化打断在途响应 |
| upstream-only | 默认请求仍走配置上游，不按裸模型切回官方 |

已知父关系即使未在后续握手重复携带，也必须继续有效。子线程模型不会修改根路由。
插件保留命名空间保持原分派/拒绝边界，不把插件模型意外送入默认桥接。

### 3. 按最终上游执行双向 WS 重连

- 新的 Responses 请求帧先解析线程树的目标路由，再比较现有连接的 `routeKind`。
- 一致则转发，CLIProxy 前缀按现有规则剥离；子线程裸模型保留自身名称。
- 不一致则不向旧上游发送该帧，沿用现有 `1012` 关闭下游并关闭旧上游的机制，
  由客户端重新握手与重放。不是在已经认证的连接上替换认证或强行换上游。
- 在重连前记录有效的新路由；新握手和 HTTP/SSE 降级使用同一份路由决定。
- side 的切换采用完全相同的机制。网关收到体现新模型选择的请求/握手时处理切换；
  若仅在 UI 更改选择而没有网络通知，网关无法在点击瞬间主动获知。
- 主线程切换不主动中止已经执行的子请求；关联线程在下一次请求时跟随。
  该边界意味着在途请求仍在旧上游完成，不能承诺切换瞬间旧上游流量归零。
- 正在执行响应时的控制帧、并发请求和异步拨号完成后的路由变更，需要明确处理，
  避免将旧连接回调误认为新的路由决定或触发重复关闭/重复发送。

### 4. 保留 turn 关联与认证隔离

- 图片请求跟随触发它的 turn 所使用的上游；主线程后续切换不改写历史 turn 归属。
- CLIProxy 路由继续剥离官方 OAuth、账号标识及其他上游密钥，注入自身 API key；
  切回官方使用该次客户端请求的官方认证，不复用 CLIProxy 连接认证。
- 日志只记录排障所需的脱敏路由信息，不暴露凭据、敏感 query 或完整请求内容。

## 风险与待验证问题

1. **旧 hint 与重连循环**：需要确认当前 TUI 收到 1012 后重发什么 hint，是否带完整
   当前模型。若仍是旧默认值，必须设计明确的路由更新优先级，不能让重连/后台握手
   覆盖刚由真实主请求确认的选择。无需改变预热时机，但不能让旧握手重新锁定路由。
2. **客户端恢复能力**：旧正向样本验证过完整 input 重放，不能据此认定当前 TUI 反向
   同样可靠。验证当前请求只执行一次、上下文和工具调用链完整；网关不自行伪造历史。
3. **父路由尚未就绪**：guardian 可能先于父路由建立。实施前确认可用父链信息，确定
   有界等待/重新判定或可恢复失败的策略；不得仅因子模型裸名就静默发送推理到官方。
4. **关联缺失**：不能凭共享 session 或时间窗口猜测父线程；缺失或断裂关联的行为须
   明确并可观测，不以“统一上游已完成”掩盖无法关联的请求。
5. **上下游并发竞态**：主线程切换期间的子请求、旧预热握手、已在途拨号可能交错。
   通过可控时序测试验证新请求使用最新有效路由，旧响应完成不会回写旧路由。
6. **旧测试语义**：旧“同线程裸标题留在 CPA”断言需按明确的新线程角色规则重审，
   不能全部替换成“裸模型走官方”；独立标题及子线程继承必须分别测试。

## 验证方式

### 自动化验收矩阵

- 同一主线程 official → CLIProxy → official → CLIProxy，多轮切换均可生效。
- TUI 默认 CLIProxy 建连后首条请求选官方，及旧连接已断、重新握手的两条路径。
- CLIProxy 根线程下的裸模型 subagent、guardian、多层子线程全部走 CLIProxy。
- 根线程切回官方后，已有子线程下一次请求和新建子线程统一走官方；再切回亦然。
- 子线程握手省略 parent 时仍保留已建立关系；两个根线程及独立标题互不污染。
- 来源主会话保持 CLIProxy，side 独立切到官方：只有 side 及其后续子请求改走官方；
  反向切换同样成立。来源主会话之后改变路由不得覆盖 side 的独立选择。
- 带 `forked_from_thread_id` 的用户线程不产生继承边，真正的 parent 继承边正常工作。
- 只有“最终目标上游变化”才重连；子线程裸模型和无模型控制帧不误触发切换。
- 路由冲突帧不进入旧上游，关闭后无重复发送；并发及异步拨号竞态确定性覆盖。
- 父节点尚未就绪、缺失/环形父链按已确定策略处理，无静默官方推理回落。
- HTTP、WS 握手及 HTTP/SSE 降级路由一致；两方向认证均正确且无凭据串线。
- 图片沿触发 turn 的路由；upstream-only、插件拦截及 Realtime 保持原行为。
