# 线程路由容量与网关测试目录隔离

> 状态：首期完成。日期：2026-11-09。

## 目标

解决[技术债追踪](../tech-debt-tracker.md)中的两条独立问题。网关限制进程内线程路由状态的增长，同时保住已有线程的上游归属。网关测试把目录、日志和其他运行产物限制在各自的临时实例，能单独运行和并行验证。

## 范围

- 线程路由：`thread-routing.ts` 的状态计量和写入预算，HTTP 与 Responses WebSocket 的超限行为，离线容量测量及路由回归。
- 测试隔离：审计五家插件和共享网关的写盘用例，补齐测试路径与依赖注入，修正已复现的网关日志路径串用，验证临时目录以外没有新增、删除或被改写的运行产物。
- 边界：两条工作可分开实现。保持现有协议、运行目录优先级和生产启动方式。真实服务重启、旧污染文件修复、线程状态落盘和客户端协议变更不在首期。

## 背景与证据

- `ThreadRoutingState` 以两个 Map 保存根路由和直接父关系。父路由未知时，当前实现会先记父边再返回 503，以便主会话就绪后子线程重试。HTTP 预热与 WS 握手也可以初始化未知根，即使后续没有推理成功。
- 现有测试明确允许已知子线程省略 parent。离线模拟整树清空并只恢复根路由，同一子线程用裸模型重试，从原来的 `cliproxy` 改为 `official`。仍携带 parent 的请求才有机会命中父链缺失保护。路由切换背景见[原执行计划](../active/responses-thread-tree-route-switch.md)，行为入口见 `apps/gateway/src/thread-routing.ts`、`gateway.ts` 和 `realtime.ts`。
- 本机用独立 Bun 进程合成 10 万个根和 20 万条父边，强制 GC 后堆增量约 32 MiB。样本为固定长度的合成 ID，未采样常驻网关的真实增长或复访时间，不能据此直接定生产阈值。
- 2026-11-01 已记录真实目录污染，ZCode 签名测试的具体缺口已修复。当前 CodeBuddy、Qoder、AGY、Zen 主要 fixture 也已注入 `cacheDirectory`，部分仍用进程级 `CODEX_CLIPROXY_HOME` 切换宿主路径。当前待办是审计其余调用点、去掉普通 fixture 对共享环境的依赖，并建立能发现漏写的回归。已有历史证据不足以断言当前分支仍污染真实目录。
- 已用两个临时目录复现现行网关日志错用路径。构造 handler 时传入显式实例，外层绑定另一实例，各有两份合法日志，开启日志并设保留一份后，外层实例少了一份，显式实例仍有两份。`resolveLogSink` 使用调用上下文，启动剪裁因此落到外层目录。Qoder 主 fixture 的国际站已注入假凭据，国内站仍存在回到本机默认凭据读取的路径。
- 上一轮验证中，整轮共用 `CODEX_CLIPROXY_HOME` 使两项 CLI 测试共享实例目录。改用独立测试用户目录并为健康检查注入空密钥后，全量 1340 项通过。该运行方式是外层防护，不能代替各 fixture 自身的隔离。

## A. 线程路由状态容量

1. **先测量。** 记录根路由数、父边数、未知父占位数、拒绝次数及父链深度分布。用小树、多层树、孤儿父链和仅预热场景测量条目数、GC 后堆与查找延迟。统计按实例汇总并限频，避免记录线程 ID、请求正文或凭据。生产预算由样本和部署内存目标决定，测试用小上限验证行为。
2. **写入前检查容量。** 预算覆盖根、父边和去重后的未知父占位，可用一次状态变更的净增量计量。校验冲突、环和容量后再统一提交，拒绝时旧状态保持完整。允许已有根改路由、已有边重试，以及用已计费的父占位补齐根路由。容量控制同时覆盖预热、握手和父路由未就绪的路径。若测得过深链明显放大查找成本，另设父链深度保护并验证正常多层链。
3. **满额时保住已有会话。** 拒绝需要新增状态的请求，使用可区分的容量错误。满额时带未知线程 ID 的无 hint 握手也应在拨号前拒绝，避免省略父关系的重试直接进入官方。HTTP 和 WS 握手在转发或拨号前返回 503。已建立的 WS 在发送触发拒绝的帧前按现有 1012 路径结束。容量已满和暂时等待父路由分别诊断，容量拒绝不能靠短间隔重试自动恢复。已有有效关系继续路由和切换。验收显式 parent 的重试以及先预热为根、后出现 parent 的边界；拒绝期间未登记的关系在解除限额后仍须由客户端重新提供，不能假定已有完整父链。
4. **单列真正的回收门槛。** 首期上限能限制内存增长，达到上限后会牺牲新线程的可用性。若需要持续接纳新线程，应先确认客户端能在复访时提供足够的父链身份、存在可靠的终止通知，或设计可重新查询的持久关联。确认契约后，才按整树回收内存，保护在途 HTTP、WS 握手和活跃连接，并让拨号后的复查区分已丢失的归属和已确认的官方路由。TTL、WS 关闭和会过期的墓碑都不足以证明历史线程不会在省略 parent 的情况下返回。

## B. 网关测试运行目录隔离

1. **盘点落盘路径和调用入口。** 以 `test/{zcode,codebuddy,qoder,agy,opencode-zen}-gateway.test.ts`、`zcode-signing.test.ts` 为起点，追查其余使用 adapter、registry、handler、真实本地监听和目录重建的用例。逐项核对插件目录、Zen 元数据、AGY 调试转储、主目录发布文件、进程日志和 Codex 缓存。记录已隔离的调用点和需要修正的调用点。
2. **沿用已有实例注入。** 每个写盘 fixture 分配独立临时目录，从同一份 `ResolvedPaths` 派生运行目录和测试 Codex 目录。组合入口传 `runtimePaths`，HTTP 日志和启动剪裁使用构造时的有效路径，两个 WS 日志入口使用监听实例捕获的路径。直接构造适配器传 `cacheDirectory` 并注入绑定该路径的宿主，需要覆盖 CLI 路径解析时使用 `runWithInstancePaths` 或专用子进程。显式注入虚构凭据、目录数据和模拟上游，覆盖 Qoder 双地域。关闭 handler、定时器和监听后再清理临时目录。保留故意在宿主作用域外消费流的回归，其消费任务仍在宿主作用域之外。
3. **验证边界而非只断言配置。** 用子进程布置虚构的默认目录和继承的运行目录覆盖值，放入哨兵文件。驱动真实的目录刷新及日志写入，确认产物在各 fixture 的临时实例，且哨兵内容、mtime 和目录清单均未变化。以临时环境做负向探针，确认漏传路径会触发检测。环境变量优先级用例继续用专门的隔离环境验证。
4. **隔离系统调用并全量验证。** 本地 WS 测试的 `startGateway` 即使允许空密钥，也会尝试读取 Keychain。给测试启动注入空或假密钥，或在独立子进程替换读取模块。实例重启测试沿用现有 launchctl 模块替身，确认只操作假实例。生产调用使用绝对命令路径，PATH 替身不能覆盖。全量检查在独立测试用户目录运行，避免用同一个 `CODEX_CLIPROXY_HOME` 覆盖全部用例，并补跑各插件测试文件和两个临时实例的并行回归。

## 风险与取舍

- **错误上游比拒绝更严重。** 路由状态达到预算时，失败请求必须在网关本地结束，已有父关系与认证域不被破坏。图片 turn 表已有独立上限，不混入线程树预算。
- **可用性受硬上限影响。** 当前契约下，内存有界、无限接收新线程和长期支持省略 parent 的历史复访无法同时满足。先依据测量确定预算和触发处置，再以实际需求决定持久关联或客户端契约。
- **外层临时目录会掩盖漏注入。** 用独立哨兵和实际文件断言校验普通 fixture。套件改动避免大范围替换宿主测试包装器，以免掩盖已有异步上下文回归。

## 验证方式

- A 定向：`bun run test -- test/thread-routing.test.ts test/realtime.test.ts`。覆盖旧树满额仍可解析和双向切换、新根及新父边原子拒绝、重复边不计重、未知父占位可补齐、预热计量、并发 WS 拨号期间状态变化、失败请求零上游发送。
- B 定向：五家 gateway、签名、目录发布/重载和宿主日志回归。覆盖测试夹具实际落盘、只剪裁所属实例、默认及覆盖目录哨兵不变、两个实例不串目录、进程环境恢复及失败路径清理。验证无需本机密钥、真实上游或生产网关。
- 集成：`bun run check`、`git diff --check`。保留仓库测试进程 60 秒上限。

### 最终测量与验证边界

独立 Bun 1.3.5 进程按根、四层树、未知父占位、单条极深链分别构造 65,536 个节点，
ID 为 128 字符。每轮构造前后调用 `Bun.gc(true)`，用 `bun:jsc` 的 `heapStats().heapSize`
测量堆增量，约为 17.1、23.8、15.1、17.1 MiB。浅树重复查找均值约 0.2 微秒，
极深链约 1.5 毫秒。这是本地合成样本，RSS 和生产长期负载需另行观测。

HTTP 日志与启动剪裁固定到 handler 的路径快照，两个 WS 日志入口固定到监听实例。
测试启动接口可以注入空密钥，覆盖回环 WS、模型重载、插件集成和 Web UI。
配置重启测试通过独立子进程的服务替身验证目标实例。
哨兵回归曾发现 CodeBuddy CLI 用例继承外部运行目录，修正后默认目录、覆盖目录及
Codex 缓存的内容、mtime 和清单均保持原样。

整树回收继续依赖可靠的父关系恢复或生命周期契约。满额后的新线程可能持续收到
容量错误，已登记树可以继续使用。进程重启后，客户端仍需重新提供未登记的父关系。
