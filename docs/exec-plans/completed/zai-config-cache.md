# /zai 授权配置缓存与目录监听

## 目标

以网关生命周期内的单个授权配置缓存替换 `/zai` 的逐请求文件读取。先建立目录监听，再首次加载形成内存快照；后续请求共享该快照，只有相关文件事件才触发重新读取。此修订覆盖 Coding Plan、Start Plan 体验套餐和 API Key 三种模式，保持两渠道的精确 provider 选择与安全直通边界。

## 范围

- 包含：当前 Z Code provider 选择、凭据及 Anthropic 地址的内存缓存，目录 `fs.watch`、100ms 防抖、串行刷新、错误状态、父目录恢复，以及停止时的资源释放。
- 包含：`src/zai-config.ts` 缓存模块、`src/zai.ts` 请求接入、`src/gateway.ts` 生命周期整合、对应本地测试与 README 说明。
- 不包含：OAuth 兑换或刷新、凭据写回、定时轮询、请求路径上的 `stat` 或文件读取、通用缓存框架、签名、握手或 PoW。
- 不包含：真实凭证读取或生产 API 验证；上游套餐及 `count_tokens` 的真实可用性仍由上游决定。

## 背景

- 配置优先级不变：`~/.zcode/setting.json` 仅在不存在时回退至 `~/.zcode/v2/setting.json`，provider 始终来自 `~/.zcode/v2/config.json`。
- 仅接受 `providerFamilyDomain` 为 `zai` 或 `bigmodel`，从当前渠道的选中值去掉第一个冒号前的模式标记后，精确读取 `provider[id].options.apiKey` 与 `baseURL`。
- 仅缓存经过校验的当前 provider 信息、凭据和 Anthropic 地址；不读取 OAuth 文件，不选择其他 provider 的备用授权。
- 模型仍完全由 Claude Code 请求指定；`/zai` 的本地 Bearer token 与上游 provider 凭据保持独立，环回监听、官方 HTTPS 地址校验及禁止重定向的边界保持不变。
- 参考主工作区同名计划；其“尚未成功发送到新任务”状态已被本轮实施消息取代。
- 最终缓存版本已独立完成完整验证：189 项测试通过，包含 23 项缓存测试。

## 风险

- 文件通过 `rename` 原子替换会使文件级监听失效：使用目录监听并过滤相关文件名，覆盖创建、修改、删除与替换。
- 目录初始不存在或被替换：监听最近存在的父目录，随目录变化重建目标目录监听；目录检查属于监听与刷新流程，不放到请求路径。
- 首次读取与监听建立间漏事件：先建立监听，再首次加载；初始化期间出现事件时重新刷新。
- 突发事件或并发请求重复读文件：相关事件立即标记待刷新，按最后一次事件进行 100ms 防抖；所有新请求共享串行刷新的等待。
- 刷新期间再次变更导致旧结果覆盖新状态：用事件版本或等价机制拒绝过时结果，直到可发布当前快照。
- 文件损坏或凭据缺失后继续使用旧授权：刷新失败清空旧快照并保存脱敏错误，新请求失败；文件修复事件触发恢复。
- 监听建立失败或运行时报错：立即使缓存不可用，关闭失效监听并明确提示重启，不能继续使用旧授权或静默退回轮询。
- 监听与计时器泄漏：网关停止及缓存 `close()` 关闭全部监听并清理防抖计时器；测试显式释放实例。

## 验证方式

- 命令：`bun run check`；测试阶段使用外部最大 60 秒超时，不以旧实现结果替代本轮检查。
- 自动验证：连续及并发请求仅首次加载文件；无相关事件时不重读、不执行请求路径 `stat`；无关文件事件不刷新。
- 自动验证：修改、原子替换、删除和重新创建均可刷新；优先设置文件出现或消失后正确切换；目录初始缺失及整体替换后可恢复。
- 自动验证：事件突发合并为防抖刷新；待刷新请求共享等待；刷新期间再更新时最终使用最新配置；已发出请求固定原快照。
- 自动验证：坏配置、缺失授权和无效 provider 使新请求失败，修复后恢复；显式 `baseURL: null` 不能被当作缺省地址。
- 自动验证：监听建立失败和运行错误给出脱敏的重启提示；停止或 `close()` 后没有残留监听、计时器或悬挂等待。
- 回归验证：现有路径与方法门控、本地鉴权、官方域名边界、模型及压缩正文直通、日志隔离、SSE 与取消传播保持原行为。
- 手工检查：README 区分 Z Code 授权配置监听与网关自身 `config.json` 的重启要求，不宣称真实账户三模式全部可用。
- 所有验证仅使用临时目录、假凭据和模拟上游，不请求生产 API。
