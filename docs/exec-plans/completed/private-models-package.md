# 私有模型预设包

## 目标

将 Codex 模型快照和厂商预设迁入 `packages/models`，通过私有 workspace 包供网关和插件直接使用，发布产物内联模型资源，不发布模型包。

## 范围

- 包含：资源迁移、直接包引用、主机预设接口移除、构建内联、发布边界与回归验证。
- 不包含：修改模型内容、远程更新策略、协议转换和真实 npm 发布。

## 背景

- 相关文档：`docs/plugin-contract.md`、`docs/monorepo-migration.md`。
- 相关代码：网关模型预设、五家插件目录、workspace 构建和发布检查。
- 参考：[CLIProxyAPI 模型定义](https://github.com/router-for-me/CLIProxyAPI/blob/main/internal/registry/model_definitions.go)，独立维护资源并通过返回副本的查询接口消费。
- 已知约束：工作树已有未提交的 monorepo 迁移；本次只调整模型资源边界。

## 风险

- 私有包引用残留会导致发布包无法运行；模型包声明为构建依赖，内联后在空白消费者验证。
- 整体打包插件会复制主机上下文；仅内联模型包，保留其他公开包依赖。
- 私有资源变更被版本工具忽略；将模型包纳入共享发布输入，发布集合仍为八个公开产品包。

## 里程碑

1. 确认私有包、模型副本与内联边界。
2. 迁移资源和所有使用方，移除应用主机接口。
3. 完成类型、测试、构建与隔离打包验证，更新文档及历史。

## 验证方式

- 命令：`bun run check`、`bun run pack:check`。
- 检查：资源内容保持一致；发布 manifest、JS 和声明不依赖私有模型包。
- 自动验证：无主机上下文调用预设接口、修改副本不污染后续读取、隔离消费者目录合成。

## 决策记录

- 2026-10-11：模型预设通过 `@agent-proxy/models` 直接导出，不再作为 HostServices 能力；保留返回独立副本的契约。
- 2026-10-11：私有模型包只作为构建依赖，数据内联进入使用方的发布产物，不进入 npm 发布集合。
- 2026-10-11（后续收敛）：ZCode 的厂商元数据仅取模型包预设，移除根目录与运行目录覆盖文件的消费路径；初始化时生成静态厂商目录，刷新和重载仅更新授权套餐投影。
- 2026-10-11（覆盖规则归属）：将原根目录 `models.json` 原样迁入 `apps/gateway/models.json`，仅允许网关内部使用，不增加包导出。该文件不再参与全包共享输入，网关项目自身的 Nx 输入及 Lerna 包内变更判定负责追踪。
- 2026-10-11（边界校验）：所有 workspace 源码的相对导入均限制在本包目录内，包括 JSON 资源，防止再次引用网关或根目录资产。
