# 模型命令职责迁移、目录更新与网关模型状态热加载

## 目标

将安装后的模式切换归入 `config --upstream-only on|off`，保留 `install --upstream-only`；`models` 只读取已保存的 `upstreamOnly`，更新选择、排除规则和目录，并据此决定是否更新 Codex 静态模型文件。模型变更通过共享更新流程热加载网关模型状态，不再因模型变化重启服务；配置模式切换等设置仍保留现有网关重启流程。CLI 与 Web UI 等待目录、受管 TOML 和安装状态就绪后，再按用户选择重载 Codex。

状态：已完成并归档。命令迁移、共享目录更新、跨进程模型热加载与静态模式生命周期已落地，bun run check 通过（类型检查、886 项测试、UI/CLI 构建）。以下背景描述实施前的问题，行为约定保留已确认边界。

## 范围

- 包含：`install`、`config`、`models` 的模式参数归属、帮助信息和迁移指引。
- 包含：模型选择与排除规则更新、agent 目录刷新生命周期、目录元数据热加载和 Codex 静态目录合成。
- 包含：CLI 与 Web UI 共享更新流程、配置保存顺序、agent 开关展示与可选 Codex 重载。
- 包含：模型更新的失败处理、备份、原子写入、受管 TOML 守卫、安装状态与审计一致性。
- 不包含：agent 请求分派与启用判定变更；由 [upstream-only 请求路由计划](upstream-only-agent-adapters.md) 承担。
- 不包含：整个配置系统的热加载；端口、agent 启停、模式切换等设置继续使用现有 `config` 重启流程。
- 不包含：改变动态模式的目录刷新策略、改变凭据刷新归属或实现新的 agent WebSocket 协议。

## 背景（实施前）

- `src/cli.ts` 当前 `models --sync` 依据是否携带 `--upstream-only` 写入模式；省略参数会切回动态模式。`models --exclude` 在规则变化时写配置并重启网关，规则未变直接返回。
- `selectedModels` 通过重建目录文件影响 `/v1/models`；`excludedModels` 当前来自启动配置，推理过滤器在创建 handler 时编译。热加载必须同时更新目录和过滤规则，不能只重新读取 `config.json`。
- agent 目录与模型集合、档位映射、协议等元数据会影响请求处理。仅替换列表响应会造成模型展示与推理状态不一致。
- CodeBuddy、Qoder、AGY、Zen 除启动和定时刷新外，`catalog()` 也可能触发 TTL 刷新；ZCode 缓存读取同样可能刷新。关闭定时器不足以实现静态模式后续只读。
- `src/upstream-catalog.ts` 的 `rebuildCatalog()` 只将已选上游写入 `config.catalogPath`；Codex 当前的 `model_catalog_json` 直接引用这份原始目录。
- `collectCompatibleModels()` 当前位于 CLI，Web UI 不能反向依赖 `cli.ts`；目录管理和更新编排应下沉到双方共用模块。
- 现有 `config` 修改在已安装服务时重启网关，agent 通常异步执行启动刷新。服务健康与目录就绪是两个独立状态，不能健康后立即重载 Codex。
- Web UI 当前可能先保存模型选择并重启 Codex，再保存其他配置；组合修改必须先收敛最终配置，再完成目录和 TOML 更新。
- 2026-08-30 曾将 `config --cpa-only` 删除并迁回 models，以便配合目录校验和 `--restart-codex`。本次迁入 config 必须同时恢复客户端重载职责，见 [历史记录](../../histories/2026-08/20260830-1707-review-fixes.md)。
- 相关代码：`src/cli.ts`、`src/config-update.ts`、`src/upstream-catalog.ts`、`src/gateway.ts`、`src/webui.ts`、`src/ui/` 与各 agent 目录模块。
- 相关计划：[协议拆分计划 §6](../active/protocol-conversion-extraction.md#6-内建-agent-路由插件试验registerprefix-fn) 提供 agent 的目录与生命周期契约；[upstream-only 请求路由计划](upstream-only-agent-adapters.md) 仅调整请求路径中对已保存模式的解释。

## 行为约定

### 1. 命令归属

- 明确保留 `install --upstream-only`，作为初次安装的布尔模式选项；这是已确认约定，不是实现建议。
- 安装后的模式切换统一使用 `config --upstream-only on|off`；无参数的 `config` 展示当前模式。
- `config` 的模式参数接受 `on|off`，安装入口仍接受布尔选项，参数解析按命令区分。
- `models` 查询、`--sync`、`--exclude` 均只读取保存的模式，不写入、不推断新的 `upstreamOnly`。只读约束针对模式字段，模型选择与排除规则仍按命令职责保存。
- 移除 models 下的 `--upstream-only`、`--cpa-only`，包括原来的 `models --sync --upstream-only`；在任何写盘前报错并给出 `config --upstream-only on|off` 的迁移指引，不静默忽略旧参数。
- 普通模型查询不写模式与模型选择、不重启服务；静态模式下只读最后成功的模型状态，不隐式刷新目录；动态模式保留现有按需刷新行为。
- `models --sync` 更新上游选择与模型目录，并协调一次 agent 目录更新；成功提交模型变更后触发运行网关的 `reloadConfig`，读取已保存的 `upstreamOnly` 决定 Codex 静态文件及受管 `model_catalog_json` 路径处理。
- `models --exclude ...` 更新本地模型排除规则，成功提交变更后触发运行网关的 `reloadConfig`；读取已保存的 `upstreamOnly` 决定 Codex 静态文件及受管 `model_catalog_json` 路径处理。规则未变沿用现有直接返回，不额外引入强制刷新。
- 两类模型更新均不再为模型变更重启网关；`--restart-codex` 保留为独立的客户端重载选项。

已实现的命令形式如下：

```bash
# 安装时初始化模式
codex-cliproxy install --upstream-only

# 配置模式，保留网关重启；目录和配置就绪后按需重载 Codex
codex-cliproxy config --upstream-only on --restart-codex
codex-cliproxy config --upstream-only off --restart-codex

# 更新模型只读取保存的模式，通过热加载生效
codex-cliproxy models --sync --restart-codex
codex-cliproxy models --exclude agy/example-model --restart-codex
```

### 2. 模型状态热加载

- 共享更新流程准备模型目录、选择结果、排除规则和 agent 元数据，校验成功并提交后，由 `models --sync`、`models --exclude` 决定触发正在运行网关的 `reloadConfig`。
- `reloadConfig` 加载模型更新影响的配置与模型状态，不直接替换整个启动配置；端口、agent 启停、模式切换等设置仍沿用现有重启路径。
- 必须重新生成 `excludedModels` 过滤器，并将最新目录、模型集合、档位映射、协议等必要元数据加载到 agent 的请求处理状态。
- `/v1/models`（及现有模型列表入口）和推理拦截使用同一轮成功更新的规则与模型状态；不能仅更新列表或仅刷新配置字段。
- 热加载保留当前连接、进行中的流和既有生命周期资源，不因更新目录重建所有服务或重复创建定时器；目录刷新成功后重新生成过滤器并发布模型状态，在途请求继续使用已取得的上下文。
- 没有运行中的服务时仍可完成目录及配置保存；不得为了执行 reload 隐式启动服务。返回信息应区分已保存、已加载和需后续启动的实际状态。
- 更新与 reload 失败必须明确报告；不能将文件写入成功描述为正在运行的网关已经加载，也不能提前重载 Codex。
- 跨进程热加载采用运行主目录内的本地通知与回执文件，按 `0600` 原子写入；通过修订标识关联每次请求与结果，网关串行处理待完成通知并保留最近 64 条回执。命令等待对应回执，区分成功、失败、超时和服务未运行；不在模型流量端口新增控制 API。
- Web UI 复用相同编排与加载契约，继续校验 ui-token、Host/Origin，并保持 UI 与模型流量端口、进程隔离。

### 3. 目录刷新生命周期

- 网关启动时保留已启用 agent 的一次自动目录刷新，包括 `config` 修改导致的重启。
- 静态模式下停止后续模型目录心跳；模型查询与推理请求不因 TTL、缓存缺失或元数据读取隐式拉取目录。
- 由目录管理层传入启动刷新、后续只读和显式更新策略；agent 插件不直接依据 `upstreamOnly` 判断自身启用或新增模式分叉。
- `models --sync`、实际改变规则的排除更新及 Web UI 对应操作复用一次性更新结果完成目录与元数据加载。交互候选与最终合成复用本轮结果；取消交互不写配置或静态目录。
- `--select none` 跳过上游目录请求，仍按本轮更新契约处理已启用 agent。
- 配置修改已要求重启时，由一次性目录准备与新进程的模型加载协调本轮结果，避免已拉取目录后再次为同一轮显式更新重复拉取；启动刷新与模型状态 ready 仍分别验证。
- `refreshCatalogOnStart: false` 仅表示关闭启动刷新，不能误认为已经关闭 TTL 和定时刷新。
- 请求继续读取当前凭据；账号变化不能复用不匹配账号的旧目录。缺少必要目录时提示执行模型同步，不偷偷刷新。
- 关闭临时目录实例及命令资源。与目录刷新共用定时器的其他维护行为应独立保留，例如 Zen 的客户端指纹更新。
- 动态模式保持现有启动、定时和按需目录刷新行为。

### 4. 静态目录与 Codex 加载

- `upstreamOnly` 为 true 时，合成已选上游模型与已启用 agent 模型，校验 ID 冲突、应用本地 `excludedModels` 后原子写入静态目录。
- 排除规则保持只作用于本地 agent 族；`selectedModels` 只管理上游选择。
- default 的上游模型使用裸 ID，agent 保留自己的前缀；不重复添加 `config.prefix`，静态目录不添加官方模型。
- 保留 agent 原有协议、档位、系统提示词、`prefer_websockets` 等元数据，不能按裸 ID 重造条目。
- 静态模式的模型列表读取最后成功的合并状态，源文件不可用时不回退拉取官方目录。
- 采用运行主目录内独立受管的 `codex-catalog.json`：保留 `config.catalogPath` 为原始上游目录，使动态目录继续使用原有数据，避免将 agent 合并结果写回上游来源文件。
- 空上游选择可以由 agent 组成静态目录。最终合并为空时拒绝更新并保留原状态，避免失去可用目录或让 Codex 回退官方模型；`--select none` 仅清空上游选择，不代表关闭已启用 agent。
- 独立快照接入 `managedCatalogFiles()`、安装状态、手动配置指引及卸载清理；不接管用户自定义目录。
- `config` 保存模式后保留网关重启，等待 agent 启动刷新及静态目录准备完成；不要求用户先手工执行 `models --sync`，也不能仅因启动前没有缓存拒绝切换。
- 切为 off 时移除受管 `model_catalog_json` 引用，恢复动态目录策略，保留上游选择、排除规则及已有缓存。
- `config` 支持可选 `--restart-codex`：目录、受管 TOML 和必要状态成功就绪后，才停止 Codex app-server 让客户端重新加载；切为 off 同样需要重读已移除的引用。
- 网关重启与 Codex 重载是独立操作。未要求重载时提示手工重启；不宣称 Codex 已自动刷新。失败不提前执行客户端重载。

### 5. Web UI、事务与安全边界

- 模式修改仅由 CLI config 负责；Web UI 只读展示 upstreamOnly，editable/提交类型不包含该字段，Web API 拒绝写入。模型更新继续复用共享管理流程，Web UI 依赖树不反向引用 CLI。
- 组合保存先收敛最终配置，再执行必要的网关重启、目录更新与 reload；所有受管配置和目录就绪后才处理 Codex 重载。
- agent 开关的禁用条件、说明文字与实际插件启用语义保持一致：撤销 upstream-only 会禁用 agent 的旧展示规则，仍按各 agent 自己的开关启用，不默认打开全部 agent。
- 延续备份、原子写入、失败恢复及只修改受管字段的行为。目录真实为空与刷新失败应可区分，不能把失败包装成空结果覆盖可用目录。
- 失败缓存仅可复用同账号的有效状态；无可用状态时报告刷新失败，不宣称本轮目录就绪。
- 两类模型更新处理 Codex 配置前先读取 `state.json` 的实际管理状态，复用 `isCodexConfigManaged` 语义判断 `codexConfigManaged`；不能只看本次命令是否携带 `--manual-codex-config`。旧安装缺省字段保持现有托管兼容规则。
- 根据已保存的 upstreamOnly 计算 Codex 目标配置：为 true 时写静态目录并关联 model_catalog_json，为 false 时使用动态目录并处理残留的受管静态引用；是否实际修改 TOML 再由托管/手动管理状态决定。
- 托管模式仅修改受管 TOML 键，保留非受管 `model_catalog_json` 守卫；手动模式不改写用户 TOML，只输出添加或删除 `model_catalog_json` 的指引，以及期望值、当前值和是否匹配。
- 托管与手动模式均可更新工具自管的模型目录文件。手动模式下目录写入成功不等于 Codex 配置已经修改，输出须分别说明。
- 手动模式的 TOML 尚未匹配目标模式和目录路径时，明确给出手工配置指引；--restart-codex 沿用用户显式请求的重载语义，不能将重载成功描述为手动配置已经修复或新目录已正确加载。
- 服务健康与目录 ready 分别观测，不能把健康检查通过当作目录更新完成通知。
- API key 存取继续走 `keychain.ts`；审计、UI 和 API 响应不暴露凭据，URL 使用既有脱敏规则。
- 修改配置字段、默认值、类型或校验规则时同步 Schema 与测试；本轮不新增用户可见的目录策略开关。

### 6. 与请求路由计划的边界

- 本计划管理命令、目录、模型状态和客户端加载；[upstream-only 请求路由计划](upstream-only-agent-adapters.md) 只处理读取已保存模式后的请求分派、启用与安全边界。
- 两份计划可独立推进、独立验证；命令迁移和模型热加载不与 upstream-only 请求变更捆绑验收。
- agent 模型合成需要 agent 提供目录与生命周期接口，复用 [协议拆分计划 §6](../active/protocol-conversion-extraction.md#6-内建-agent-路由插件试验registerprefix-fn) 的契约；目录操作不通过请求前缀注册表派发。
- 接口可以先在现有适配器上落实，再与协议拆分统一。实现顺序不要求请求路由改造先完成，也不因此扩大本计划为转换器重构。

## 风险

- 风险：只重读配置或只更新列表，推理仍使用旧排除规则或 agent 元数据。
  - 缓解：测试同一轮目录、过滤器与请求元数据一致；明确完整模型状态加载边界。
- 风险：模型热加载破坏进行中的流、重复创建资源或扩大为全面配置 reload。
  - 缓解：保留在途请求与连接，检查定时器及 close 次数；配置重启与模型加载分开。
- 风险：只停心跳，TTL、查询或推理仍隐式刷新。
  - 缓解：分别记录启动、显式更新、查询、推理和定时器触发的目录请求次数。
- 风险：异步启动刷新尚未完成，Codex 已加载旧目录。
  - 缓解：服务健康与目录 ready 独立；实际发布成功后才能执行 `--restart-codex`。
- 风险：配置、目录、TOML 与运行中模型状态半更新或热加载结果不可观测。
  - 缓解：准备与发布分离，沿用原子写入和备份；报告每阶段真实结果，收敛通知和失败恢复契约后实施。
- 风险：迁移参数时继续隐式改模式，或静态目录误伤用户的非受管文件。
  - 缓解：旧命令写盘前拒绝并给指引；覆盖安装、手动配置、非受管 TOML 与受管文件边界。

## 里程碑

1. 固化命令职责与模型状态边界，采用本地通知/回执、独立快照与最终空目录拒绝策略。
2. 迁移 config/models 参数、帮助和兼容报错，保留安装入口及 config 网关重启；接入 config 的可选 Codex 重载。
3. 实现共享一次性目录更新和网关模型状态 reload，覆盖过滤器、agent 元数据及静态模式生命周期。
4. 接入静态合成、受管 TOML、安装状态与安全守卫；调整 Web UI 保存顺序和 agent 开关说明。
5. 独立完成命令与热加载回归，运行必需检查、记录实现历史并归档本计划；请求路由计划另行验收。

## 验证方式

- 参数：`install --upstream-only` 保留布尔形式，`config --upstream-only on|off` 正确解析，旧 models 模式参数在写盘前拒绝并给出迁移指引。
- 模式：两种模式下的模型查询、同步和排除均不改变 `upstreamOnly`；省略模式参数的同步不会切回动态模式。
- 热加载：同步和实际变化的排除更新成功提交后触发 `reloadConfig`，不重启网关；模型列表与推理过滤使用新状态，agent 档位、协议及模型元数据一致。
- 资源：reload 不中断在途流、连接，不重复创建定时器；reload 失败和无运行服务时报告实际状态，不隐式启动服务。
- 刷新：静态模式启动保留一次刷新，后续 TTL、查询和推理不隐式更新、不创建目录心跳；动态模式保持既有刷新行为。
- 更新：交互候选与合成复用本轮结果，规则未变仍 no-op，取消不写盘；配置重启与已取得结果协调避免重复拉取。
- 切换：config 不要求预先同步；网关健康但目录未 ready 时不重载 Codex。on/off 都在所需目录和 TOML 成功发布后才执行可选重载。
- 目录：仅 agent、仅上游、混合、空选择、最终为空、ID 冲突、来源失败、账号变化和损坏目录边界；最终空静态目录必须拒绝并保留原数据，独立快照不得污染原始上游目录。
- 管理模式：通过已保存的 `state.json` 判断托管或手动，而非依赖本次安装参数；两者都能更新自管目录，手动模式的 TOML 始终不改写，正确展示添加/删除指引及匹配状态，Codex 重载结果不误报为手动配置已经修复。
- 安全：非受管 TOML 守卫、备份恢复、凭据脱敏、UI 鉴权与模型端口隔离均保持。
- UI：最终配置先保存，再更新目录与客户端；agent 控件不因 upstream-only 禁用，说明文字与自身启用开关一致。
- 命令：每次后台单元测试最长 60 秒；提交前运行 `bun run check`，涉及 UI 时运行 `bun run build:ui` 并验证生成结果。最终全量检查完成前，不将本计划标记为完成。
