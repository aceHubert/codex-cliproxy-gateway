# 插件流式日志上下文与 AGY 未声明工具容错

> 状态：已完成。2026-11-09 在修复分支完成实现、全量回归和隔离打包验收。

## 目标

修复 CodeBuddy 流式日志在主机作用域外消费响应时丢失的问题，核实并处理 Qoder 的
同类回调；让 AGY 遇到未声明工具名时保留有效响应，通过保守映射或忽略并提示收尾，
不因单个未知工具将整轮响应判为失败。这是两个独立实现切片，共同对应技术债中的
“插件流式响应的容错与日志遗留问题”。

## 范围

- 日志切片：`packages/codebuddy/src/index.ts`；Qoder 先复现，证据成立再修改
  `packages/qoder/src/index.ts`；覆盖流完成、失败、取消及多实例隔离。
- 工具切片：`packages/agy/src/response.ts` 及必要的包依赖声明；覆盖 AGY 已支持的
  Responses、Chat Completions、Anthropic、Gemini 客户端输出与流式/非流式行为。
- 对应测试、必要文档和完成后的历史记录。
- 不包含：修改 OpenCode Zen 日志路径；它的 tee/then 模式探针未复现同类故障。
- 不包含：重新改写已经修复的 AGY/ZCode 日志机制、主动调用真实上游、部署或重启、
  配置字段变更、WS 路由计划的剩余验收。
- 不扩大容错至畸形 JSON、缺失工具名、无效参数对象或真正的上游协议错误。

## 方案

### A. 恢复日志回调的主机上下文

1. 请求入口仍在有效主机作用域内时捕获当前 host，不在流消费时重新猜测所属实例。
2. 用 `withHostServices(host, ...)` 包住统一的 log/finish 日志执行路径，覆盖
   logExchange、logGatewayError、logRequestSummary。复用已有模式，不增加全局host变量，
   不用 enterWith 长期改变调用方上下文，不扩大 plugin-api 的全局行为。
3. 审查 onComplete、失败回调、取消及超时清理路径：维持一次性收尾，日志最多记录一次，
   取消请求释放计时器和上游资源；日志失败不能使成功的业务响应变成失败。
4. 保留现有脱敏和日志开关策略。Qoder 不增加提示词、私有认证头和工具内容转储。
5. Qoder 若完整适配器复现不能成立，记录调用机制及结果，不为形式一致而添加代码。
   此时该部分结论应是“未复现，依据已记录”，不能声称修复了未经证实的线上故障。

### B. AGY 未声明工具容错

1. `options.tools.get(name)` 精确命中继续原流程，保留 name、namespace、custom形状。
2. 未命中时复用已有 `remapUndeclaredToolName`：仅骨架与唯一声明键一致时映射，
   歧义和零命中不猜测，不模糊匹配任意工具，更不能执行映射表之外的工具。
3. 未能映射时抑制该调用，不生成 function_call/custom_tool_call，不伪造执行结果；
   注入简短可见文本，说明忽略了未声明工具，保留其他有效文本和合法工具调用。
4. 所有工具均被忽略时，各协议应正常结束并包含提示，不产生“需要工具结果但没有
   工具调用”的终态。上游真实失败、取消和长度截断保留其原有语义，不伪装成功。
5. 在发出工具条目及关联签名前完成名称判定；合法/唯一映射工具保留 thoughtSignature
   与 `agn1:` 信封。被忽略调用不留下孤立签名或工具块，也不把其签名挪给下一个工具。
6. 优先从 `@agent-proxy/llm-bridge` 的公开 export 复用现有函数，不复制归一算法。
   实施时显式增加 AGY 的 workspace 依赖并更新锁文件，核对包构建顺序和打包依赖。
   不允许跨包相对导入源码；若依赖成本不合适，先记录替代设计再变更边界，
   不借此重构整个 AGY 协议转换链。

## 风险与处理

- **主机实例串线**：两个实例交错读取流，日志必须落回各自目录；禁止共享可变host。
- **取消造成重复日志或资源泄漏**：结合现有幂等标志验证一次性清理，不重复关闭上游。
- **误映射工具**：只允许声明表唯一匹配；相同骨架多候选必须抑制，测试验证不调用错误工具。
- **流中段已经输出有效内容**：后续遇未知工具时保留已输出文本，事件序号、条目ID及终态一致。
- **签名与工具分离**：覆盖签名附着在functionCall及独立part的两种形态，验证后续历史回放。
- **新增依赖影响发布**：构建、边界检查及隔离打包验证包exports与依赖可用，不执行真实发布。
- **测试掩盖ALS故障**：测试本身的host-test上下文可能让原代码也通过；必须使用在任何
  withHostServices之外创建的消费任务，并以实际文件结果判断，不能只断言mock被调用。
- **测试污染本机配置**：全部凭据、缓存、日志使用临时目录和虚构数据；不访问真实账号，
  不写默认运行主目录；测试结束用finally关闭适配器并清理临时资源。
