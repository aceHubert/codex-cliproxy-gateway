# CodeBuddy auto 双地域目录、模型同步与显示格式

> 状态：已完成。用户恢复实施后，完成全量检查、真实登录及本机现有服务的 HTTP 验收。
> 代码保持未提交，其他任务的既有修改保留。

## 目标

auto 模式依据本地 `.info` 登录所支持的地域，同时发现并展示 CN 与国际版模型；
模型同步及客户端推送使用同一份双地域目录。Web 和 `codebuddy --switch` 的自动项
显示为 `Auto(account / intl)` 或 `Auto(account / cn)`，保存值仍为 `auto`。

## 最终需求与验收边界

1. **目录按真实登录决定地域**：两地均有可用 `.info` 登录时，同时展示
   `codebuddy-cn/*` 和 `codebuddy-intl/*`；只有一地时只产出该地目录。
   不把国际版模型清单镜像成国内版，各地分别用对应凭据拉取实际清单。
2. **请求与账号锁定保持一致**：继续使用模型前缀指定地域；同地域产品回退规则不变。
   账号锁定时只展示该账号所选登录支持的地域，不借目录枚举跨账号或跨地域回退。
3. **缓存分别保存**：保留 `codebuddy-catalog.json`、`workbuddy-catalog.json`
   两个产品文件名，文件内部按 profile 保存各地目录、账号身份键、时间和内容指纹。
   一地失败不覆盖另一地缓存，重启可恢复两地目录，账号变化不复用旧账号清单。
4. **模型同步覆盖两地**：`models --sync` 通过适配器刷新两地目录；
   `models --push` 离线读取当前可用登录匹配的两地缓存，并保留完整地域前缀。
   现有排除规则、客户端自身排除项及目标客户端的模型范围规则继续生效。
5. **只改变 Auto 显示格式**：Web 与 CLI 统一为 `Auto(account / intl|cn)`；
   括号内复用现有账号标签及地域，无有效账号时显示 `Auto`。
   不改变账号选项、当前命中账号的折叠、选择索引、取消行为或账号选择逻辑。
   Auto 是所选模式，括号内账号只是当前按 auto 规则解析出的信息。

## 风险

- 风险：同产品两地缓存相互覆盖，切换账号后误复用旧目录。
- 缓解方式：文件内按 profile 保存独立缓存，继续核对账号身份摘要与内容指纹；旧单目录缓存只按匹配 key 迁移。
- 风险：枚举缺失地域或锁定账号的另一地域时，每次都触发认证目录全扫。
- 缓解方式：先使用 `.info` 的内存缓存快照；部分地域缺失直接跳过，仅所有组合均不可用时补扫一次。
- 既有边界：新增另一地域登录依赖凭据监听更新快照；已有一地有效而新增事件未被监听捕获时，
  本次目录枚举不主动重扫。继续依靠后续监听、缓存刷新或请求容错更新，不引入周期性全扫。
- 风险：把 Auto 的显示变更误扩展为账号选择行为调整。
- 缓解方式：仅修改标签拼接，保留原过滤与选项值，并验证 CLI 选择和取消行为。
